01 วันสำคัญ

วัน deploy

deploy ขึ้นเครื่องทดสอบ 3 รอบ แล้วขึ้น server จริง 1 ครั้ง

วันเหตุการณ์ที่ไหน
จันทร์ 12 ต.ค.เริ่มงาน ล็อก spec โครงสร้างข้อมูล และรูปแบบ API ให้จบภายใน 13 ต.ค.ทีม
พุธ 14 ต.ค.เครื่องทดสอบพร้อม: 1Panel, PostgreSQL, SSL, ขั้นตอน deploy จาก GitHubเครื่องทดสอบ
พฤหัส 15 ต.ค.deploy รอบ 1: login และบทความเครื่องทดสอบ
จันทร์ 19 ต.ค.deploy รอบ 2: ผลงานอ้างอิงเครื่องทดสอบ
พุธ 21 ต.ค.deploy รอบ 3: แคตตาล็อก แล้วหยุดเพิ่มฟีเจอร์เครื่องทดสอบ
21 ถึง 22 ต.ค.ทดสอบเต็มชุดและแก้ข้อบกพร่องเครื่องทดสอบ
ศุกร์ 23 ต.ค. เช้าdeploy ขึ้น server จริง ย้ายเนื้อหา ชี้โดเมน เฝ้าดูทั้งวันserver จริง
26 ถึง 30 ต.ค.สัปดาห์กันชน: แก้สิ่งที่หลุด พนักงานร้านทดลองใช้ ทดสอบกู้ข้อมูลสำรองserver จริง
ศุกร์ 30 ต.ค.เส้นตายสุดท้าย ตรวจรับลูกค้า

02 บทบาท

ใครทำอะไรใน 2 สัปดาห์

1 คนควบหลายบทบาทได้ Backend กับ Frontend ทำพร้อมกันได้เมื่อรูปแบบ API ล็อกแล้ว

บทบาทสัปดาห์ 1 · 12 ถึง 16 ต.ค.สัปดาห์ 2 · 19 ถึง 23 ต.ค.
Lead / PMล็อก spec และรูปแบบ API ใน 2 วันแรก แจกงาน นัดลูกค้ารับเนื้อหารีวิวโค้ดรายรอบ ตัดสินว่าข้อบกพร่องใดต้องแก้ก่อนขึ้นจริง อนุมัติ deploy 23 ต.ค.
Backendตารางฐานข้อมูล 3 ส่วน, login, API บทความ, API ผลงานAPI แคตตาล็อก, อัปโหลดรูปและ PDF, ภาพย่อจาก PDF, สคริปต์ย้ายเนื้อหาตัวอย่าง
Frontend หลังบ้านโครงหน้า admin, หน้า login, ฟอร์มบทความ, ฟอร์มผลงาน (หลายรูป เลือกสินค้า)ฟอร์มแคตตาล็อก, ข้อความแจ้งข้อผิดพลาด, คู่มือใช้งานสั้นสำหรับพนักงาน
Frontend หน้าเว็บเลิก static export, หน้าบทความและผลงานอ่านจากฐานข้อมูลหน้าแคตตาล็อกและการค้นหาใช้ข้อมูลใหม่, เปลี่ยนตัวนับสถิติ, เชื่อมแบบฟอร์มติดต่อ, ตรวจ SEO และ sitemap
DevOpsตั้งเครื่องทดสอบให้พร้อมภายใน 14 ต.ค., ขั้นตอน deploy, สำรองข้อมูลอัตโนมัติตั้ง server จริง, Umami, Uptime Kuma, deploy 23 ต.ค., ชี้โดเมนและอีเมล
QAเขียนรายการทดสอบจาก spec ทดสอบรอบ 1 ทันทีที่ขึ้นเครื่องทดสอบทดสอบรอบ 2 และ 3, ทดสอบเต็มชุด 21 ถึง 22 ต.ค.: หลังบ้าน 3 ส่วน มือถือ สองภาษา สิทธิ์เข้าหน้า admin

03 กันชน

สัปดาห์ที่ 3

เว้นไว้รับสิ่งที่ผิดแผน ถ้าไม่มีอะไรหลุด ใช้เวลานี้กับการทดลองใช้ของลูกค้า

บทบาทงานในสัปดาห์กันชน · 26 ถึง 30 ต.ค.
ทุกบทบาทแก้ข้อบกพร่องที่พบหลังขึ้นจริง ไม่เพิ่มฟีเจอร์ใหม่
DevOpsทดสอบกู้ข้อมูลจากชุดสำรอง 1 ครั้ง ตรวจการแจ้งเตือนเมื่อเว็บล่ม
QAทดสอบซ้ำหลังแก้ ตรวจบน server จริงทุกหน้า
ลูกค้าพนักงานร้านทดลองเพิ่มบทความ ผลงาน และแคตตาล็อกเอง แจ้งแก้ไขภายใน 28 ต.ค.
Lead / PMตรวจรับกับลูกค้า 30 ต.ค.

04 ความเสี่ยง

จุดที่ต้องระวัง

  • แคตตาล็อก การสร้างภาพย่อจาก PDF เสี่ยงล้นมากสุด ถ้าไม่ทัน 21 ต.ค. รอบแรกทำแค่อัปโหลด PDF ให้ดาวน์โหลด ตัวดูทีละหน้าย้ายไปสัปดาห์กันชน
  • เครื่องทดสอบ ต้องพร้อม 14 ต.ค. ทุกบทบาทอื่นรออยู่
  • รูปแบบ API ต้องล็อกภายใน 13 ต.ค. ไม่เช่นนั้น Backend กับ Frontend ทำพร้อมกันไม่ได้
  • การทดสอบ ทดสอบทุกรอบทันทีที่ขึ้นเครื่องทดสอบ ไม่รอถึง 21 ต.ค.
  • เนื้อหาจากลูกค้า ถ้าได้ช้ากว่า 16 ต.ค. เว็บจะขึ้นจริงด้วยเนื้อหาตัวอย่าง แล้วพนักงานใส่เองผ่านหลังบ้าน
  • deploy วันศุกร์ ทำช่วงเช้าเพื่อเฝ้าดูได้ทั้งวัน และมีสัปดาห์กันชนรองรับ

05 ยังไม่ได้ตัดสิน

ต้องตอบก่อนเขียน spec

  • ทีม จำนวนคนและความถนัด เพื่อจับคู่คนกับบทบาท
  • เครื่อง สเปก RAM CPU ดิสก์ และเป็นเครื่องเฉพาะของ ITERRA หรือใช้ร่วม
  • เทคโนโลยี รวมหลังบ้านใน Next.js ตัวเดิม หรือแยก backend เป็นบริการต่างหาก
  • ที่เก็บไฟล์ เก็บรูปและ PDF บนดิสก์ของเครื่อง หรือที่เก็บภายนอก
  • แผนลูกค้า เอกสารแผน 4 สัปดาห์และงวดจ่ายเดิมไม่ตรงกับร่างนี้ ต้องแก้เมื่อร่างนิ่ง
