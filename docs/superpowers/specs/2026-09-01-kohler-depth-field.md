# สนามภาพเชิงลึก — เข้าเว็บและแกลเลอรี

Addendum · branch `prototype-uxui`

## 1. ที่มา

ลูกค้าชี้ michaelgatt.com แล้วบอกว่าอยากได้แบบนี้: ภาพกระจายอยู่ในอวกาศ ซูมเข้ามาจากข้างนอก
เลื่อนเมาส์แล้วเดินดูได้ เลือกได้ — ทำทั้ง**หน้าโหลด**และ**แกลเลอรี**

## 2. วัดของจริงมาแล้ว

| | michaelgatt.com |
|---|---|
| เทคนิค | **WebGL2 + three.js** (`__THREE__` อยู่ใน window) |
| canvas | 1 |
| **`<img>` ในหน้า** | **0** |
| เมาส์ | ขยับไปมุมซ้ายบน → **พิกเซลเปลี่ยน 57% ของทั้งจอ** = กล้องเลื่อนทั้งสนาม |
| องค์ประกอบ | ~40 ระนาบ ขนาดและความลึกต่างกัน พื้นดำ ตัวหนังสือลอยกลางจอ + "INDEX VIEW" |

## 3. ทำไมเราไม่ใช้ WebGL

canvas ไม่มี `<img>` แปลว่า: ไม่มี alt · ไม่มี lazy load · crawler มองไม่เห็นสักรูป ·
ไม่มี DOM ให้โฟกัสเกาะ

เว็บเขาเป็นพอร์ตโฟลิโอนักแต่งเพลง ไม่มีใครค้นหารูปในนั้น
**เว็บเราเป็นแคตตาล็อกสินค้า 182 ชิ้นที่ต้องถูกค้นเจอและใช้คีย์บอร์ดได้** และ AC ทุกฉบับที่ผ่านมา
วัด alt กับ focus ring — canvas ตกทุกข้อ

ใช้ **CSS 3D** แทน: `perspective` บนกล่องนอก + `transform-style: preserve-3d` +
`translate3d` ต่อระนาบ ได้หน้าตาเดียวกันที่ ~40–60 ระนาบ ซึ่งเป็นจำนวนที่ของเขาใช้อยู่แล้ว
ไม่เพิ่ม dependency (สนามนี้ทำด้วย GSAP ที่มีอยู่แล้วได้ทั้งหมด)

สิ่งที่ยอมสละ: depth-of-field blur ต่อระนาบแบบจริง และจำนวนระนาบระดับพัน
ทั้งสองอย่างไม่จำเป็นสำหรับสินค้า 182 ชิ้น

## 4. ที่เอาไปใช้

### 4.1 ประตูเข้า — แทน preloader ปัจจุบัน

- สนามลึก ~40 ระนาบ เป็น**รูปสินค้าพื้นโปร่ง**ปนกับ**รูปห้องจากคลังไลฟ์สไตล์**
  (มี 170 ใบแล้ว — ห้อง 68 รายละเอียด 57)
- เปิดมากล้องอยู่ "ข้างนอก" สนาม แล้ว**ซูมเข้า**ตามความคืบหน้าการโหลดจริง
  ไม่ใช่ timer — กติกาเดิมจากงาน J ยังอยู่
- โหลดครบแล้วกล้องหยุด เลื่อนเมาส์เดินดูสนามได้
- ปุ่มเข้ากดได้ตั้งแต่วินาทีแรก · `ESC` ข้ามได้ · กติกาห้ามขังผู้ใช้ยังอยู่

### 4.2 แกลเลอรี — route ใหม่

- สนามเดียวกันแต่เป็นสินค้าล้วน เลื่อนเมาส์เดินดู
- คลิกระนาบ → ไปหน้าสินค้านั้น **พร้อมเฉดที่เห็นอยู่** (ใช้ `?finish=` ที่ทำไว้แล้ว)
- มีปุ่มสลับเป็น "มุมมองดัชนี" = กริดธรรมดา — ของเขามี "INDEX VIEW" และมันจำเป็น
  เพราะสนาม 3D หาของเฉพาะเจาะจงไม่ได้

## 5. ข้อบังคับ

1. ทุกระนาบเป็น `<img>` จริง มี alt จากข้อมูล ตามภาษา
2. **คีย์บอร์ดต้องเดินสนามได้** — Tab ไล่ระนาบตามลำดับตรรกะ ไม่ใช่ตามตำแหน่ง 3D
   ระนาบที่โฟกัสต้องถูกดึงเข้ามาหากล้องให้เห็นชัด และ focus ring ต้องอยู่บนสุด
   (บทเรียนจาก `0581815`: `inset` box-shadow วาดใต้ลูก `absolute` ทุกตัว)
3. `prefers-reduced-motion`: ไม่มีซูม ไม่มีการเลื่อนตามเมาส์ — แสดงเป็นกริดนิ่งทันที
4. มือถือ: ไม่มีเมาส์ให้เลื่อน → กริดเลื่อนแนวตั้งธรรมดา ไม่ต้องจำลอง 3D ด้วยการเอียง
5. `transform`/`opacity` เท่านั้น · `will-change` เฉพาะระนาบที่ขยับจริง
   · หยุดทุกอย่างเมื่อสนามพ้น viewport
6. รูปในสนามต้องเป็นไฟล์ที่หน้าอื่นใช้อยู่แล้ว (กติกาเดิมจากงาน J) และใช้ variant 700/900
   ไม่ใช่ 1400/1800

## 6. Acceptance criteria

1. ประตูเข้า: ≥ 30 ระนาบ เป็น `<img>` ทั้งหมด มี alt ครบ · กล้องซูมตาม % จริง · ปุ่มกดได้ที่วินาทีแรก
2. เลื่อนเมาส์แล้วสนามขยับจริง — วัดว่า `transform` ของกล่องสนามเปลี่ยนตามตำแหน่งเมาส์
3. Tab เดินได้ครบทุกระนาบ · ระนาบที่โฟกัสถูกดึงเข้ามาและมองเห็น focus ring ชัด
   วัด contrast บนระนาบที่สว่างที่สุดและมืดที่สุด
4. reduced-motion แสดงกริดนิ่ง ไม่มี transform ค้างกลางทาง
5. 390px เป็นกริดแนวตั้ง ไม่มี horizontal overflow
6. แกลเลอรี: คลิกระนาบไปหน้าสินค้าถูกตัวและ**เฉดตรงกับที่เห็น** · สลับมุมมองดัชนีได้
7. Lighthouse ยัง ≥ 85 บนหน้าที่มีสนาม
8. AC เดิมทุกฉบับยังผ่าน

## 7. ความเสี่ยง

| # | เรื่อง | จัดการ |
|---|---|---|
| 1 | 40 ระนาบ + `preserve-3d` = compositing layer เยอะ อาจกระตุกบนเครื่องอ่อน | จำกัด 40–60 · `will-change` เฉพาะที่ขยับ · หยุดเมื่อพ้นจอ · วัด FPS จริงก่อนส่ง |
| 2 | ซูมเข้าจากข้างนอกทำให้ระนาบใหญ่มากช่วงต้น = fill rate พุ่ง | เริ่มจาก scale ที่ยังเห็นทั้งสนาม ไม่ใช่ซูมจากระยะประชิด |
| 3 | สนาม 3D หาของเฉพาะเจาะจงไม่ได้ | มุมมองดัชนีเป็นข้อบังคับ ไม่ใช่ของเสริม (§4.2) |
| 4 | รูปห้องปนรูปสินค้าโปร่งในสนามเดียวกัน อาจดูมั่ว | รูปห้องอยู่ชั้นลึก ทำหน้าที่เป็นฉากหลัง · สินค้าโปร่งอยู่ชั้นหน้า |
