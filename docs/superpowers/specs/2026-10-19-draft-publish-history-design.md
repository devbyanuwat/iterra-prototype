# ร่าง เผยแพร่ และประวัติการแก้ไข

ร่างวันที่ 19 ตุลาคม 2569 · สถานะ: lead อนุมัติแผนในแชตแล้ว (งานย่อย 1 จาก 6)

## ทำไม

ตอนนี้กดบันทึกในหลังบ้านแล้วขึ้นหน้าเว็บทันที และ `audit_log` จดแค่ว่าใครแก้อะไร ไม่เก็บเนื้อหา ย้อนกลับไม่ได้
lead ต้องการแบบ WordPress: แก้แล้วยังไม่ขึ้นเว็บจนกว่าจะกดเผยแพร่ มีประวัติทุกฉบับ และเลือกฉบับเก่ากลับมาใช้ได้

## งานย่อยทั้งหมด (เรียงตามที่ lead รับ)

1. ตาราง `revisions` กับขั้นร่าง เผยแพร่ ย้อนกลับ เฉพาะสินค้า (เอกสารนี้)
2. ขยายไปผลงาน บทความ ประกาศ
3. แถบแอดมินบนหน้าเว็บจริง ดูร่างด้วย `draftMode()` และปุ่มเผยแพร่
4. ปุ่มแก้ไขบนหน้าเว็บ เปิดแผงข้างจอด้วยฟอร์มชุดเดิม
5. ข้อความประจำหน้าจาก `lib/i18n.ts` ย้ายไป DB
6. บอกและเช็กข้อจำกัดการอัปโหลดในเบราว์เซอร์ (พิกเซล ความยาววิดีโอ ชนิดไฟล์)

ไม่ทำรอบนี้: ประวัติของวิดีโอหน้าแรกและ PDF แคตตาล็อก, หมวด แบรนด์ วัสดุ

## ข้อมูล

```sql
create table revisions (
  id           bigint generated always as identity primary key,
  entity       text not null,              -- 'product' ตอนนี้ งานย่อย 2 เพิ่ม 'project' 'post' 'announcement'
  entity_id    bigint not null,            -- ไม่มี FK เพราะชี้ได้หลายตาราง · ลบสินค้าแล้วลบประวัติด้วยในโค้ด
  data         jsonb not null,             -- เนื้อหาทั้งชิ้นแบบเดียวกับฟอร์ม
  user_id      bigint references admin_users,  -- null = ฉบับตั้งต้นก่อนเริ่มเก็บประวัติ
  at           timestamptz not null default now(),
  published_at timestamptz                 -- null = ร่าง
);
```

- คอลัมน์ในตาราง `products` คือฉบับที่ขึ้นหน้าเว็บ หน้าเว็บอ่านที่เดิม ไม่ต้องแก้
- ร่าง คือ revision ล่าสุดของสินค้านั้นที่ `published_at` เป็น null
- การแสดงหรือซ่อน (`published`) ไม่อยู่ใน `data` ยังเป็นสวิตช์ที่มีผลทันทีเหมือนเดิม เผยแพร่ร่างแล้วตั้งเป็นแสดงด้วย

## พฤติกรรม

- **บันทึกร่าง**: ตรวจข้อมูลแบบเดียวกับตอนบันทึก (รวม slug ซ้ำกับสินค้าอื่น) แล้วเพิ่ม revision ร่าง หน้าเว็บไม่เปลี่ยน
  - สินค้าใหม่: สร้างแถวใน `products` แบบซ่อนไว้ก่อน เพราะต้องมี id
  - สินค้าเดิมที่ยังไม่มีประวัติ: เก็บฉบับที่ขึ้นเว็บอยู่เป็น revision ตั้งต้นก่อน (เผยแพร่แล้ว ไม่มีผู้แก้) ไม่งั้นย้อนกลับไปฉบับแรกไม่ได้
- **บันทึกและเผยแพร่**: บันทึกร่างแล้วเผยแพร่ใน transaction เดียว
- **เผยแพร่**: เขียน `data` ของร่างลงคอลัมน์ ตั้งแสดง แล้วติด `published_at` ให้ revision นั้น ไม่มีร่างแล้วกดได้ข้อความผิด
- **ประวัติ**: ในฟอร์มแก้ไข เปิดดูรายการ revision ใหม่สุดก่อน บอกวันเวลา ผู้แก้ และสถานะ
- **ย้อนกลับ**: กด "ใช้ฉบับนี้" แล้วเนื้อหาฉบับนั้นโหลดเข้าฟอร์ม จากนั้นบันทึกร่างหรือเผยแพร่ตามปกติ ประวัติเดิมไม่ถูกลบหรือแก้
- **ลบสินค้า**: ลบ revision ของสินค้านั้นด้วย (กู้คืนไม่ได้อยู่แล้วตามข้อความเดิม)
- รายการสินค้าในหลังบ้านติดป้าย "มีร่าง" เมื่อมีร่างรอเผยแพร่ เปิดฟอร์มแล้วได้เนื้อหาของร่าง
- audit: บันทึกร่าง `update` · เผยแพร่ `publish` (detail มีเลข revision)

## ทางเลือกที่ตัดสินเอง

- ย้อนกลับทำในฟอร์ม ไม่มี Server Function แยก: น้อยโค้ดกว่า และผู้ใช้เห็นก่อนว่าจะได้อะไร
- ไม่มีปุ่มทิ้งร่าง: ย้อนกลับไปฉบับที่เผยแพร่อยู่แล้วบันทึกร่างให้ผลเท่ากัน
- ไม่จำกัดจำนวน revision: สินค้าราวร้อยชิ้น แก้ไม่บ่อย ถ้าโตเกินค่อยเพิ่มการล้างใน `db-prune.mjs`
